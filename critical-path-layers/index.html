Critical Path Layers

A strategy framework for decisions taken under speed and uncertainty.
Five sequenced acts of diagnostic work. Each layer feeds the next. Each gate must clear before downstream work converts. Click a layer to expand it.

L1 Situational awareness
Layer 1
Situational awareness
Read the terrain.
What you produce
  • A current map of what has moved in the last quarter
  • The dependencies you have not audited
  • One assumption you used to hold that is no longer true
Gate L1 → L2
You can name three things that have changed since the last strategy review, the dependency each one breaks, and one assumption you used to hold that is no longer true.
L2 Dependency map
Layer 2
Dependency map
What depends on what.
What you produce
  • A dependency graph in fewer than twenty nodes
  • Upstream, downstream, and lateral dependencies named
  • The translation from domain to dependency (the sales problem is a Layer X problem)
Gate L2 → L3
Another competent operator can recognise the graph you have drawn.
L3 Binding constraint
Layer 3
Binding constraint
Which dependency is load-bearing right now.
What you produce
  • The binding constraint, named in one sentence
  • The diagnostic that surfaced it, documented
  • The cost of being wrong, explicitly accepted

Gate L3 → L4
The binding constraint is named in a single sentence, the diagnostic that surfaced it is documented, and the cost of being wrong is explicitly accepted.
L4 Gated sequence
Layer 4
Gated sequence
Order of work plus gates.
What you produce
  • The sequence of work that resolves the binding constraint
  • Gate criteria for each step, testable by someone who is not the operator
  • An explicit pause on downstream work until the upstream gate clears
Gate L4 → L5
Sequence is named, each criterion is testable by someone who is not the operator, and the team has explicitly accepted that downstream work waits.
L5 Constraint rotation
Layer 5
Constraint rotation
Watch the triggers.
What you produce
  • A written set of trigger conditions, each tied to a Layer 1 assumption
  • A named owner who watches them
  • A re-entry plan for Layer 1 when a trigger fires
↻ When a trigger fires
Return to Layer 1. Re-read the terrain. The binding constraint you locked at L3 may have moved. This is the loop most frameworks omit. Without it the stack ossifies.

Gate L5 (loop)
The team holds a set of trigger conditions, each tied to a specific assumption from Layer 1, that when observed force a return to Layer 1. The conditions are written down. Someone is responsible for watching them.
Cross-cutting dynamics
Independent of the layer you are working on, each of these can derail the work at any time.
Founder or owner bottleneck
Personal bandwidth, identity, or decision-making becomes the binding constraint.
Organisational immune response
The system protects its current state by neutralising work that does not fit the existing performance engine.
Downstream gravity
The pull toward layers further down the chain when the upstream gate is unresolved. The most common failure mode.
Narrative drift
The story diverges from the work. Once they diverge, the work loses internal legitimacy regardless of its merit.
